# Screenshots

Generated by `shots/ModDbShots.cs`, not hand-taken, so the set can be reproduced after a
visual change. **The images themselves are not tracked** — only what makes them. Run:

```bash
bash scripts/make-shots.sh              # dizzyd@vsclient.home by default
```

`06-icon-source.png` is not part of the set; it is cropped square to `06-icon-candidate.png`
at 480x480. **Nothing writes over `Packrat/modicon.png`** — the shipped icon is authored and
committed, and CakeBuild copies it into the release zip, so a script that replaced it would
change what every download looks like as a side effect of taking screenshots. Copy the
candidate over it by hand if it is ever wanted.

## The scene

A brick storeroom, enclosed on purpose. Packrat opens every container in the room the player is
standing in, and only containers within about five blocks when there is no room, so an
open-topped set would quietly switch the scan to its outdoor rules and half these containers
would not be in the window.

Thirteen containers of six types — chests, trunks, a labelled chest, baskets, a storage vessel
and crates — because "every container" is the claim and a wall of identical chests does not
demonstrate it. They are stocked deep rather than with a token stack apiece: the browser shows
every slot of every container, empties included, so a lightly-stocked storeroom photographs as
a window of blanks.

Two traps the scene hit while it was being built, both of which fail silently:

- **A trunk is two blocks long.** It writes a multiblock part into the cell beside it — a
  south-facing one to its west, a west-facing one to its north — and that part overwrites
  whatever is already there. Two containers vanished from the room and from the window this
  way. `VerifyPlaced` exists to say so the next time this layout is moved around.
- **Every position has to go through `P()`.** A bare `BlockPos` is a world position, and the
  runner hands each test a plot out in that world, so building with raw coordinates puts the
  room near the world origin in an unloaded chunk: `SetBlock` succeeds, no block entity is ever
  created, and the frame comes back showing empty ground.

`OpenBrowser` logs what the window actually received, because a scene that comes back looking
thin is usually a container that never answered and that is invisible in the frame itself.

## What the shots need that a normal test run does not

- **A real window.** vstestkit's client template runs at 960x600 for deterministic visual
  baselines. `make-shots.sh` swaps the template for the boot and puts it straight back — the
  template lives inside the slot's own checkout, so no other tenant on the box sees it, and it
  is only read at boot anyway. It then asserts the window really came up at 1920x1080.
- **Not shadows.** Asking for `shadowMapQuality` on this headless GL setup crashes the client at
  startup with *FBO ShadowmapFar: One or more attachment points are not framebuffer attachment
  complete*. That crash is worth failing loudly on: swallow it and `run.sh` simply boots its own
  session with the restored template, and you get small shots that look fine until you open them.
- **The HUD.** `ICoreClientAPI.HideGuis` is read-only, but the minimap, block tooltip, hotbar
  and stat bars are all `GuiDialog`s and close on request. The hotbar and stat bars reopen
  themselves regardless, so the frames are cropped from 1920x1080 to 1690x909 to cut them off.
- **The chat, which is the exception.** `HudDialogChat` is not even in `OpenedGuis` until
  something opens it, it only holds what was said after it came up, and it does not come back
  once closed — so `HideHud` never closes it, `Shot05` opens it with the `chatdialog` hotkey
  before saying anything, and closes it again afterwards so it does not sit in the corner of
  every later scene. Its panel is anchored bottom-left, which is why that one frame gets its
  own crop box.
- **`TriggerChatMessage`, not `SendChatMessage`.** `.packrat` is a *client* command;
  `SendChatMessage` sends to the server and it is swallowed there with no output and no error.
- **The seraph's hand.** Ordinary first person floats it in the corner of every frame;
  `immersiveFpMode` renders the body from the eyes instead and keeps it out.
- **The block selection outline.** Drawn on whatever the player is aiming at, and not a dialog
  that can be closed. Taking the player's reach away with `PickingRange` is what stops it;
  Packrat's own range rule is a fixed 5.1 blocks and does not read that, so the browser still
  opens on everything it would open on normally.
- **The crosshair**, which cannot be closed either but is not drawn at all while a GUI has the
  mouse ungrabbed. That is free in the four window shots. The icon crop is taken left of centre
  instead.

`VSTK_SHOT_DIR` is exported for the **boot**, not for `run.sh`. It is read inside the game
process, and `run.sh` reuses whatever session is already up — set it on `run.sh` and the game
that is already running never saw it, the shots land in the fallback `/tmp`, and the fetch
finds nothing.
